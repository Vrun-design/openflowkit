# Product

## Register

Product.

## Users

OpenFlowKit serves developers, platform and cloud engineers, software architects,
technical product teams, and educators who need to turn systems thinking into
clear, editable diagrams. They value speed, precision, interoperability, and
control over where their work is stored.

## Product Purpose

OpenFlowKit is a local-first diagramming studio for builders. It combines direct
canvas editing, structured diagram semantics, code and AI-assisted generation,
automatic layout, broad technical icon coverage, and professional export without
requiring an account. The product should make a first useful diagram immediate
while preserving enough structure for serious architecture and engineering work.

## Brand Personality

Precise, capable, calm, and quietly ambitious. OpenFlowKit should feel like a
well-made technical instrument: approachable on first contact, fast under expert
hands, and honest about the state of the user's work. Delight comes from fluid
control and thoughtful detail, not spectacle.

## Anti-references

- Generic AI SaaS dashboards that make the assistant more prominent than the work.
- Playful sketch-only whiteboards that trade precision and semantics for novelty.
- Dense legacy enterprise diagram tools with modal-heavy, form-first workflows.
- Decorative futuristic GPU demos whose effects reduce legibility or predictability.

## Design Principles

- **Structure without constraint.** Preserve diagram meaning while allowing free-form positioning, routing, styling, and composition.
- **Direct manipulation first.** Selection, movement, connection, and editing must feel immediate and reversible.
- **Local-first trust.** Keep user work private by default and make persistence, export, and recovery behavior explicit.
- **Progressive power.** Make the common path obvious; reveal advanced controls at the moment they become useful.
- **One canvas, many representations.** Visual editing, code, imports, AI, and exports must operate on the same canonical document.
- **Performance is interaction quality.** Frame stability, input latency, and predictable feedback are product features.
- **Accessible by construction.** Keyboard, assistive technology, reduced motion, contrast, and non-pointer workflows are core behavior.

## Accessibility & Inclusion

Target WCAG 2.2 AA for application controls and authored UI. Every essential
canvas action needs a keyboard-accessible equivalent, visible focus, meaningful
labels, and a non-color-only state cue. Respect reduced-motion and system theme
preferences. Keep language direct, avoid blame in errors, and preserve user work
through recoverable failures.
